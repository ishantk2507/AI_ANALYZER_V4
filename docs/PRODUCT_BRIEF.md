# Product brief

**Product:** AI Analyzer  
**Working version:** V4 baseline; V5 direction is proposed  
**Owner:** Solo developer  
**Status:** Product definition for planning; not a user-validated market claim

## 1. Product statement

AI Analyzer is a local-first analytical workspace that lets people ask questions about structured data in natural language, inspect how an answer was calculated, and turn useful analyses into repeatable workflows.

The product's differentiator is not that an LLM can write code. It is that a constrained local model can compose verified analytical capabilities while a deterministic runtime owns data access, calculations, validation, and provenance.

## 2. Problem

People with CSV, Excel, or Parquet data often need recurring analysis but lack the time or skills to write queries, maintain dashboards, or reproduce calculations. Generic chat-based analysis can produce plausible explanations without reliably preserving filters, units, denominators, or calculation assumptions.

## 3. Initial target user

Start with analysts and operations/finance users in small teams who:
- Work with structured tabular data.
- Need ad-hoc comparisons, rankings, trends, and summaries.
- Prefer local processing or need control over where data is sent.
- Repeat some analyses as new files or periods arrive.
- Need to explain and reproduce the result.

Do not optimize the first release for every possible user group. Data scientists, researchers, executives, educators, and non-technical spreadsheet users are useful secondary personas, but their requirements should be validated separately.

## 4. Jobs to be done

1. **Understand a dataset:** What is in this file, what is missing, and what can be analysed?
2. **Answer a question:** Calculate a result with the intended measure, filters, dimensions, and time period.
3. **Explain the result:** Show what was compared, what the result means, and what caveats apply.
4. **Inspect the evidence:** Reproduce the calculation and trace each claim to computed facts.
5. **Repeat the work:** Save a validated workflow and run it against updated data.

## 5. Product principles

- Correctness before fluency.
- Ask rather than silently guess when intent is ambiguous.
- Never execute arbitrary model-generated Python, shell commands, or unrestricted SQL.
- Every material claim should be linked to computed evidence.
- Local-first is a data-handling property that must be documented and tested, not just a marketing phrase.
- Simple mode and advanced mode share the same computation engine.
- A failed or unsupported request is better than a confident misleading answer.
- Reusable workflows are versioned, inspectable, and user-approved.

## 6. Experience modes

### Simple mode
- Dataset overview and suggested questions.
- Plain-English answers and readable charts.
- Visible comparison period and filters.
- Caveats in ordinary language.
- Export and save workflow actions.

### Advanced mode
- Selected dataset and semantic roles.
- Validated plan and execution steps.
- Full result table and calculation details.
- Data-quality diagnostics.
- Run trace, timings, and provenance.

These are presentation modes over one runtime, not separate analysis systems.

## 7. Scope boundaries

### Initial supported scope
- Local CSV and Parquet.
- Profiling and schema inspection.
- Filtering, grouping, aggregation, sorting, pivoting, safe derived metrics.
- Rankings, period comparisons, basic descriptive statistics.
- Tables, charts, exports, saved queries/workflows.
- Deterministic execution and structured validation.

### Explicitly out of scope until separately designed
- Arbitrary Python or shell execution generated by the model.
- Unattended actions on external systems.
- Automatic business decisions or recommendations in high-impact domains.
- Claims of statistical causality from descriptive data.
- Multi-tenant hosted deployment without isolation and security work.
- Automatic model fine-tuning from unreviewed user feedback.

## 8. Product success measures

Track task completion, numerical correctness, filter integrity, misleading-answer rate, clarification success, reproducibility, time to useful result, p50/p95 latency, and tokens per successful answer.

Do not use message count, number of agents, or chart count as proxy measures of product value.

## 9. Non-goals

AI Analyzer is not intended to replace a data warehouse, a governed enterprise BI platform, a statistical review process, or a human domain expert. It should make common analysis easier while exposing limitations honestly.

## 10. Positioning sentence

A private, local-first data analyst that turns natural-language questions into inspectable, repeatable analytical workflows—with deterministic calculations and evidence-backed answers.
